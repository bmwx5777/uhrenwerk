# Запуск в production

Документ для того, кто будет разворачивать проект. Описан путь на Vercel +
управляемый Postgres — он самый короткий для Next.js. Приложение не
привязано к Vercel: это обычный Node-сервер, его можно запустить где
угодно, где есть Node 20.9+ и доступ к Postgres.

## 1. База данных

Подойдёт любой управляемый Postgres **версии 13 и выше** (в схеме
используется `gen_random_uuid()`), проверено на 18. Варианты:

| Провайдер | Замечания |
| --- | --- |
| Neon | ближе всего к бессерверной модели, есть ветки под preview-окружения |
| Supabase | кроме базы даёт хранилище файлов — пригодится для фото товаров |
| Hetzner / свой сервер | дешевле на объёме, но бэкапы и обновления на вас |

Важно для серверных окружений: если база за пулером в **transaction mode**
(Supabase pooler, pgbouncer), prepared statements не поддерживаются.
В [src/server/db/index.ts](src/server/db/index.ts) есть пометка — там нужно
добавить `prepare: false` в настройки подключения.

## 2. Переменные окружения

Задаются в панели хостинга, не в репозитории. Приложение проверяет их на
старте схемой Zod ([src/lib/env/server.ts](src/lib/env/server.ts)) и
падает с понятным сообщением, если чего-то нет — это намеренно: лучше не
запуститься, чем работать вполовину.

```
DATABASE_URL="postgresql://user:password@host:5432/dbname?sslmode=require"
BETTER_AUTH_SECRET="<32+ случайных байта>"   # openssl rand -base64 32
NEXT_PUBLIC_APP_URL="https://uhrenwerk.example"

# Письма: без ключа транспорт падает в production (это намеренно)
RESEND_API_KEY="re_..."
EMAIL_FROM="UHRENWERK <orders@uhrenwerk.example>"

# Задача снятия просроченных резервов; без секрета эндпоинт отключён
CRON_SECRET="<24 байта hex>"                  # openssl rand -hex 24

# Реквизиты для проформы при оплате переводом
BANK_BENEFICIARY="UHRENWERK LTD"
BANK_IBAN="CY.."
BANK_BIC="BCYPCY2N"
BANK_NAME="Bank of Cyprus"
```

`BETTER_AUTH_SECRET` задаётся один раз: его смена разлогинивает всех
пользователей. `NEXT_PUBLIC_APP_URL` должен точно совпадать с рабочим
доменом — от него строятся ссылки в письмах, canonical-адреса и карта
сайта.

Появятся на этапе 8 (платежи и письма): ключ почтового провайдера, ключи
платёжных провайдеров и секреты для проверки подписи вебхуков.

## 3. Миграции

Миграции **не применяются автоматически при сборке** — это сделано
осознанно: сборка может запускаться параллельно в нескольких местах, а
менять схему должен один управляемый шаг.

```bash
DATABASE_URL="postgresql://…" npm run db:migrate
```

Порядок при обновлении: сначала миграции, потом деплой кода (если
миграция совместима с прежней версией кода), либо короткое окно
обслуживания, если нет.

## 4. Сборка и запуск

```bash
npm ci
npm run build
npm start
```

На Vercel команды подставляются сами. Для контейнера пригодится
`output: "standalone"` в [next.config.ts](next.config.ts) — он уменьшает
образ, но для Vercel не нужен.

## 4a. Задача по расписанию

Снятие резерва с неоплаченных заказов — обычный HTTP-эндпоинт, закрытый
секретом:

```
GET /api/cron/release-reservations
Authorization: Bearer $CRON_SECRET
```

На Vercel расписание уже описано в [vercel.json](vercel.json) (каждые
10 минут) — платформа сама добавляет заголовок с `CRON_SECRET`. На своём
сервере подойдёт системный cron:

```
*/10 * * * * curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://домен/api/cron/release-reservations
```

Без заданного `CRON_SECRET` эндпоинт отвечает 503 и ничего не делает:
открытый адрес, отменяющий заказы, был бы подарком любому желающему.

## 5. Что проверить перед открытием магазина

- [ ] **Почтовый провайдер подключён** (`RESEND_API_KEY`, `EMAIL_FROM`).
      Без ключа транспорт намеренно падает в production. Путь через
      HTTP API Resend написан, но живым ключом не проверялся — отправьте
      тестовое письмо первым делом.
- [ ] **Банковские реквизиты заполнены** (`BANK_IBAN`, `BANK_BENEFICIARY`):
      без них страница оплаты показывает предупреждение вместо счёта.
- [ ] **Карты и криптовалюта подключены.** Сейчас доступен только
      банковский перевод; остальные способы видны покупателю с пометкой
      «подключается». Реестр провайдеров — `src/server/payments/registry.ts`.
- [ ] **Ставки НДС сверены с бухгалтером.** Значения в сиде — на октябрь
      2026; ставки меняются решениями правительств.
- [ ] **Регистрация в OSS.** Флаг `OSS_REGISTERED` в
      [src/lib/constants/tax.ts](src/lib/constants/tax.ts): без него
      кросс-бордер B2C в ЕС считается по кипрской ставке (допустимо до
      порога 10 000 € в год).
- [ ] **Юридические тексты.** `/terms` и `/privacy` содержат рабочие
      заготовки, их должен дополнить юрист.
- [ ] **Реквизиты компании** на `/about` и в подвале.
- [ ] **Ограничение частоты** перенесено в Redis, если инстансов больше
      одного: сейчас счётчики живут в памяти процесса
      ([src/server/rate-limit.ts](src/server/rate-limit.ts)).
- [ ] **CSP переведён в рабочий режим.** Сейчас заголовок отдаётся как
      `Content-Security-Policy-Report-Only` — он ничего не блокирует, но
      показывает нарушения в консоли браузера. Включать принудительно
      имеет смысл после того, как станут известны домены платёжного
      провайдера.
- [ ] **Бэкапы базы** настроены и проверены восстановлением.
- [ ] **Мониторинг ошибок.** В коде расставлены `console.error` с
      контекстом; отправку в Sentry или аналог нужно добавить.

## 6. Хранилище изображений

Загрузка фотографий из админки работает: файлы сохраняются в
`public/uploads/products` и отдаются как обычная статика. Проверяются
роль, размер (до 8 МБ) и подпись файла — расширению и Content-Type
из браузера код не верит.

**Важное ограничение.** Локальный диск подходит для разработки и для
своего сервера с постоянным томом. На Vercel и в контейнерах без тома
файловая система недолговечна: загруженные фотографии исчезнут при
следующем деплое. Там нужен объектный storage — Cloudflare R2, S3 или
Supabase Storage.

Переход на него — это второй драйвер в
[src/server/storage/index.ts](src/server/storage/index.ts): интерфейс
`storeImage` остаётся, вызывающий код (route handler и админка) не
меняется. После подключения добавьте домен хранилища в
`images.remotePatterns` в [next.config.ts](next.config.ts) — без этого
`next/image` откажется отдавать картинки.

Поле «добавить по адресу» в админке остаётся: оно нужно, когда
фотографии уже лежат в CDN или приходят от поставщика.

## 7. Производительность

Что уже сделано:

- шрифты self-hosted через `next/font` — нет запросов к Google и сдвига
  вёрстки при загрузке;
- `next/image` с явными `sizes` на всех изображениях;
- главная и список брендов перегенерируются по расписанию (`revalidate`),
  каталог и карточка товара динамические — там всегда актуальные остатки;
- запросы каталога идут одним SQL с агрегатами, без «N+1»;
- пул соединений к базе один на процесс.

Что стоит сделать на реальном трафике:

- заменить `revalidate` на адресную инвалидацию по тегам
  (`revalidateTag`) при изменении товара в админке — обновление станет
  мгновенным;
- включить `cacheComponents` в Next и разметить динамические участки
  (корзина, сессия) — каталог будет отдаваться из кэша целиком;
- посмотреть реальные Core Web Vitals (Vercel Speed Insights или
  web-vitals) и оптимизировать по ним, а не по предположениям.
